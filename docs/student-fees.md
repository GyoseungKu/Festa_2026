# 학생회비 납부자 명단 및 자동 확인

## 관리자 사용 방법

- 메뉴: **학생회비 납부자 관리**, `/admin/student-fees`
- ADMIN·SUPER_ADMIN만 접근·추가·검색·삭제할 수 있습니다. STAFF는 접근할 수 없습니다.
- 엑셀을 열어 **제목 행을 제외한 학번 열만 복사**하고 입력칸에 붙여넣습니다. 파일 업로드/암호 해제는 지원하지 않습니다.
- 정상 10자리 숫자, 또는 앞 4자리 + `**` + 뒤 4자리만 허용합니다. `2022**0062`는 `2022100062`로 변환합니다.
- 줄바꿈·탭·공백·쉼표·세미콜론으로 구분합니다. 최대 10,000개/200,000자입니다.
- 중복은 건너뛰며 **기존 명단에 추가**합니다. 새로 붙여넣은 명단으로 전체 교체하지 않습니다.
- 형식 오류가 하나라도 있으면 전체 입력을 거부하고 잘못된 항목 순서를 알려줍니다. 원본 학번은 오류 메시지에 노출하지 않습니다.
- 학번 전체·부분 검색과 마스킹 학번 검색을 지원하며 페이지당 20개를 표시합니다.
- 삭제하면 해당 학번의 납부자 등록이 해제됩니다.

납부자 명단은 사용자 계정 목록과 별개입니다. 아직 가입하지 않은 학생도 명단에 등록할 수 있으며, 명단 등록만으로 계정을 만들거나 학생인증을 부여하지 않습니다.

## 학생인증과 연동

| 학생인증 | 명단 일치 | studentFeePaid |
|---|---|---|
| 미인증/회수 | 관계없음 | false |
| 인증 완료 | 일치 | true |
| 인증 완료 | 불일치 | false |

- 학교 SSO 인증 완료 시 학교에서 받은 학번으로 확인합니다. 승인 대기 중에는 학생인증/납부 혜택을 부여하지 않고, 승인 완료 시 확인합니다.
- 관리자가 학생인증을 부여할 때는 백엔드가 SSO 사용자 프로필의 학번을 조회해 확인합니다. 프론트가 보낸 학번으로 납부 상태를 바꾸지 않습니다.
- 명단 추가·삭제 시 기존 인증 사용자도 즉시 재검증합니다. 기존 학교 인증 해시가 없는 관리자 인증 사용자는 SSO에서 학번을 가져옵니다.
- 인증 회수 시 납부 상태도 false가 됩니다. 인증 학번이 바뀌면 새 학번으로 확인합니다.
- 재검증은 변경 요청의 DB 트랜잭션 안에서 수행합니다. 별도 비동기 큐가 아니며, 응답 성공 시 반영 완료입니다. SSO 조회 등 재검증 실패 시 명단 변경도 롤백합니다.
- 명단 변경/학생인증은 DB 공통 잠금으로 직렬화합니다. 직접 DB를 변경하는 작업에는 적용되지 않습니다.

## 프론트 응답

내 정보(`MeResponse`), 사용자 검색·QR 조회(`QrUserView`), 관리자 학생인증 변경 응답에 `studentFeePaid: boolean`을 추가했습니다. 기존 접근 권한과 개인정보 마스킹은 유지합니다.

```js
const feeLabel = !user.schoolVerified
  ? "학생인증 필요"
  : user.studentFeePaid ? "납부" : "미납부";
```

미인증 상태의 false를 곧바로 미납부로 표시하지 마세요. 클라이언트가 납부 여부를 직접 수정하는 API는 없습니다. 명단 관리 자체는 서버 렌더링 관리자 페이지에서 제공합니다.

## 저장 및 운영

- `student_fee_payers`: 학번(10자리 PK), 비교용 HMAC 해시, 등록 시각·관리자 UUID. 관리자 검색·조회 때문에 이 별도 명단에는 학번 원문을 저장합니다.
- `festival_users.student_fee_paid`: 기본 false인 납부 확인 결과.
- `festival_users.student_fee_subject_hash`: 인증 시 비교용 학번 해시. 사용자 테이블에 학번 원문을 추가하지 않습니다.
- `student_fee_lock`: 동시 변경 제어용 1개 행. 서버 시작 시 없으면 생성합니다.
- 기존 `school_subject_hash`와 동일한 `SYU_SSO_SUBJECT_HASH_SECRET`을 사용합니다. 비어 있으면 기존 정책대로 학교 SSO client secret을 사용합니다. 최소 16바이트가 필요하며, 기존 학교 인증 데이터가 있다면 키를 임의로 변경하면 안 됩니다.
- 현재 기본 `ddl-auto=update`에서 신규 테이블·컬럼을 생성합니다. 운영에서 다른 정책으로 덮어썼다면 배포 전에 스키마를 준비하세요.
- 명단은 개인정보이므로 접근·백업을 제한하세요. 프록시/APM에서 검색 query와 POST 본문(학번 명단)을 수집하지 않도록 설정하세요. 관리자 화면은 `Cache-Control: no-store`를 반환합니다.
